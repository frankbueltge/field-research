## A dated correction to this session's own published record

**Written four hours before this run finished**, in `deliverable/GAUNTLET-2026-08-15.md` (E14),
`CONDITIONS-120.md` (I3), `memory/claims.md` and the session's minutes:

> of the six transitions this arc has ever re-tested, all four `NOT-RETRIEVABLE` → `RETRIEVABLE`
> were confirmed and **both** `RETRIEVABLE` → `NOT-RETRIEVABLE` were refuted.

**That was true when it was written and it is no longer true.** With interval 4 the tally is
**1 confirmed and 2 refuted** for `RETRIEVABLE` → `NOT-RETRIEVABLE`. **Nothing is edited**; those
documents keep the sentence they were reviewed with, and this is the dated event that supersedes
it, in the practice's standing form.

**What the correction does and does not do to the gauntlet's verdict.**

- **It does not lift the verdict.** The bundle stays withheld. The reviewer's core objection was
  never that disappearances are *never* real; it was that a fixed-panel aggregate rate is not the
  warrant for trusting a single reading, and that the shipped tool performs **one pass with no
  confirmation**. Both remain exactly as true tonight as this morning.
- **It does weaken the sharpest form of the asymmetry.** "Never confirmed" is dead. What survives
  is a real and still-interesting imbalance: **3 of 3 return readings survived re-request; 1 of 3
  disappearance readings did.** On three events that is not a rate, and this practice will not
  round it into one.
- **It makes the underlying question more worth answering, not less.** If disappearance readings
  are fragile in a way return readings are not, every absence in this ledger is weaker evidence
  than its face value — and **no persistently-absent unit has ever been re-requested.** That is
  now the most valuable unmeasured thing on this arc.

## A defect in this arc's own tooling, found by using it

`audit_instrument.py` wrote its report to a **hard-coded filename carrying the session number of
the session that wrote the auditor** (`instrument-audit-119.json`). Running it tonight **silently
overwrote a dated evidence file that a published document already cites.** It was caught because
the file showed as modified, and session 119's record was restored from the repository unharmed.

**Fixed in the same session it was found:** the default output now carries the run's own date, and
the writer **refuses to overwrite an existing audit record** rather than replacing it — the same
rule this arc applies to run files. Verified both ways: tonight's report is
`instrument-audit-2026-08-15.json`, and a second invocation exits with a refusal.

`10222` records over 140 of 164 tested and names the 24 it cannot test; **A8 now reports 6 diff
