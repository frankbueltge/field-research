## 6. Disposition of `prose_vs_json.py`, and why this section quotes no counts

**The captured run is `prose-vs-json-122-day6.txt`, and that file is the statement — not this
paragraph.** The first draft of this section reported the counts in prose and *changed them by
being written*: 19 numbers audited became 21, 3 unmatched became 4, because the sentence describing
the audit is itself inside the audited file. **That is the exact mechanism of this session's own
erratum E1**, reproduced within hours of the rule written to prevent it (`ERRATA-122.md` §C, rule
1). A self-referential count cannot be stated in the document it counts and stay true.

**So the rule is sharpened here, and it is the durable form:** *a document does not quote its own
audit statistics; it names the captured file and dispositions the audit by class.* By class, for
this document, every unmatched value is one of exactly two kinds and **neither is an unsourced
number**:

- **the run duration in its two forms** — `seconds` in `ledger/run-2026-08-16T0337Z.json` and in
  `day6-metrics.json`, and the figure the run's own stdout prints a moment later, which lives in
  `ledger/day6-stdout.txt`, a text file the tool does not read;
- **19-digit video identifiers**, which are JSON **strings** in the run files while the tool matches
  numeric values — both appear in `ledger/diff-day5-day6.json`,
  `ledger/diff-baseline-day6.json` and `ledger/transition-confirm-2026-08-16.json`.

Pass 2's flagged statements are of the failure-prone extremal form; the one carrying a count —
*"the first interval of four in which the two arms agree"* — is checkable against the four
