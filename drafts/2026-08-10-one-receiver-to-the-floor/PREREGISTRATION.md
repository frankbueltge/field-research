**It is not a concept gate.** No arc opens today and no measurement is staked on anything here.

## The order of work, fixed in advance — the void hunt comes first

This inverts the order every previous session used, because the asymmetry is the defect:

1. **VOID HUNT, BEFORE ANY PASS IS RECORDED.** The need is **presumed met** until we have failed to
   find the artifact that meets it. We look for: the platform's own research-interface changelog and
   documentation; the group's own later publications and repository commits; any third party
   publishing the same quantity. Only a failed hunt licenses "unmet", and the hunt is documented
   whether it succeeds or not.
2. **THE FLOOR PASS.** The paper's full text (not its abstract); the artifact links the paper itself
   resolves to; the code repository and its issue tracker; the dashboard, fetched and its current
   state described; the authors' institutional and personal pages; the group's blog if it has one.
3. **ONLY THEN, THE SCREENS**, in the order session 107 measured as the working one: consumable
   first (S4 killed 5 of 5 that reached it), then unmet, then named/dated.
4. **THE ADVERSARY**, on the exact committed state.

**Route rule (standing, from session 107).** A page that fails one route is retried on another before
anything depends on it. If it still fails, the row does not pass that screen, and no outcome is
recorded as "provisional on a page we could not open."

**Standing check (fifth-occurrence form).** Ask what the object already publishes about itself, and
try to derive the finding from that first — **run it on the number as well as the claim, and run it on
the candidate we like, not only on the one we are ready to lose.** This session's whole subject is a
candidate we like. That is the test.

## Predictions, before the first fetch

Falsifiable, scored honestly in `RESULT.md` whichever way they fall.

- **P1.** The paper is retrievable at the reported URL, and its authors and date match what our
  register reports. *(If they do not, the register's unopened rows are worse than we said.)*
- **P2.** The paper documents a running instrument of the authors' own — a dashboard or daily check —
  reachable today at a URL derivable from the paper.
- **P3.** That instrument's scale is small (order tens of items, not millions). *If it is large, the
  need is theirs to meet and not ours.*
- **P4.** The group has published something after the paper's date that extends, closes or moots the
  gap, findable in one focused search.
- **P5 — the prediction that kills the candidate, and we expect it to hold.** The void hunt finds a
  public artifact that already supplies, in whole or in substantial part, the quantity the paper asks
  for. *We predict the death of the candidate we like, because predicting only the deaths we are ready
  to accept is the documented defect.*
- **P6.** The measurement the group needs requires credentials or access this practice does not have
  and cannot obtain in 25 days. *This is the session-104 failure one level up: a receiver whose
  instrument we cannot feed.*
- **P7.** The adversary breaks at least one load-bearing statement of this session. *(Held at 104,
  105, 106 and 107.)*

## The kill criterion, written before the first fetch

**The candidate dies today, and this session ends with a one-page negative and no gate, if ANY of:**

- **(a)** the void hunt finds a public artifact that already supplies the quantity asked for; or
- **(b)** after the floor pass we cannot name **one specific artifact** this practice could build —
  from a data route we have actually established, not one we assume exists — that this named group
  could use; or

  obtain.

**"Established data route" means:** a URL that returned bytes to a command run in this session, with
the command and the byte count recorded. Not a documented endpoint. Not an API we believe exists.
