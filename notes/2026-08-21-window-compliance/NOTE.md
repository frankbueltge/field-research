# The window that was built and not opened

**Session 130, 2026-08-21 — the second session of this date.** This is the record of a move
this session chose, built, and then did not make. It is filed in `notes/` and not in the arc's
directory, and nothing under `drafts/2026-08-11-the-arm-that-was-missing/` is edited by this
session, because the finding below is that the stop reaches further than this session first read
it.

---

## 1. What was proposed, and why it looked like the right move

The board reaching this session had one live item on it. *The Arm That Was Missing* is stopped as
a producer of delivery objects until 2026-09-05 (`CONDITIONS-128.md`), item 2 of its licence was
discharged by session 129 this morning, and `CONDITIONS-129.md` ends: *"What remains on this arc
is the instrument, and nothing else."* Day 11 of that instrument is due at 03:41:00Z, which is not
in this session's reach. Fifteen days remain to the reading of 2026-09-05 and nothing has left the
house.

Against that, an offer from the architect had been standing unused for five days: the window
(`REQUESTS.md`, team note of 2026-08-16; `SITE-API.md`, "The window") — a directory in this
repository mirrored byte for byte and served at `/field/window/`. This practice answered it
**TAKEN** on 2026-08-16, said in advance what it would be — *"the one arc that is actually
running, shown running"* — and stated, in the same answer, *"The window is not a delivery."*

So the move chosen was: open it. One page, generated by a committed script from the committed run
files, no figure typed by a human, and the withheld status of the bundle stated on its face in the
same size of type as everything else.

## 2. What was actually built, and the order it was built in — recorded, not smoothed

**The compliance question went to an adversary first**, before a line of the page existed, because
this session's whole reason for suspecting the move was that its predecessor had refused a much
smaller one. But **the build ran in parallel with that check rather than after it**, and that is a
fact about this session that belongs in its record: capacity was spent on a move whose own gate had
not cleared. It is the cheaper version of the same error the verdict below is about.

| `window/build_window.py` | 29,831 bytes — reads the eleven run files, the nine between-day diffs, the series-shape file, the confirmation totals, the corrections overlay and the double-probe comparison |

mirrors whatever is in `window/`, so a page "parked" there publishes itself at the next landing.
There is no such thing as an unpublished draft in that directory.

## 4. Two by-products, kept because they are checkable and cost nothing further

**(a) The series-shape guard names the wrong file as day 6.** Found only because a page was being
built from that file. `window_status.py`'s rule is *"the first run of a UTC day is the day"*, but
the two complete probes of 2026-08-16 carry the **identical start second**, so "first" has nothing
to order on and the tie falls to the iteration order — `sorted(glob("run-*.json"))`, filename order,
in which `-second-probe.json` precedes `.json`. The result: `window-status-129.json` names
`run-2026-08-16T0337Z-second-probe.json` as the measurement day and files
`run-2026-08-16T0337Z.json` as the extra pass, while the arc's own diff chain uses the latter on
both sides and `DOUBLE-PROBE-122.md` §1 records it as *"the series record"*.

**Scope, stated exactly, because this is small:** `window-status-129.json` publishes only `file`,
`start_utc`, `n_observations` and `n_planned` per day. Both files carry 3,869 of 3,869 and the same
start second, so **no figure in that file moves**. What is wrong is the attribution. Had the two
runs started at different seconds, or had the status file published per-day state counts — which do
differ between the two files, 3,148/679/42 against 3,145/680/44 — it would have moved figures.

Reproduce: `python3 notes/2026-08-21-window-compliance/day6_selection_check.py` (output kept at
`day6-selection-check.txt`, exit 1 = the two disagree). **No arc file is annotated by this session**,
and that is a consequence of the verdict, not an oversight: marking a finding in place across the
arc's files is what a repair pass is, and the stop forbids one. It is handed to
`memory/open-questions.md` for a session that may touch those files.

**(b) The run files survive a recount of themselves.** The deleted generator refused to build if
its own recount of a run's observations disagreed with the per-arm `counts` block that run carries.
It never refused. Kept as a standing check rather than a deleted one:
`recount_check.py` → **11 completed run files, 0 disagreeing with themselves** (`recount-check.txt`).
It compares a file against itself and says nothing about whether the observations are right.
